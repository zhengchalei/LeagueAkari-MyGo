## 测量方法

在本人战绩加载完成后，使用 [测量脚本](../scripts/measure-memory.ps1) 递归收集助手主进程与所有子进程；将 `WorkingSet64` 和 `PrivateMemorySize64` 相加并除以1048576。MyGo表中的7个进程包含Go宿主与WebView2浏览器、GPU、网络、渲染等子进程。进程更多不代表总内存更高。

```powershell
$taskApp = Get-Process -Name LeagueAkari-MyGo
./scripts/measure-memory.ps1 -RootProcessId $taskApp.Id -Application LeagueAkari-MyGo -Version 0.5.0
```

工作集是当前驻留内存；相加会重复统计进程之间共享的物理页，不代表系统独占物理内存。私有提交是私有已提交虚拟内存，不等同于当前RAM驻留量。内存会受英雄图片、战绩页数、缓存、窗口数量、后台裁剪和运行时间影响。

## 实现差异

- Go替换Electron/Node桌面宿主，使用Windows已有WebView2运行时，可执行文件内嵌前端；不分发完整Electron运行时。
- 默认每人20场战绩摘要，完整详情与时间线按需读取；不保留界面不使用的missions对象。
- 手动时间线最多缓存4场，页面最多缓存2个；对局变化清理有关数据。
- 同一对局不反复读取全部玩家战绩；辅助窗口仅在请求显示时创建。
- Go设置160MiB软内存上限用于垃圾回收节奏，不是整个进程树的硬上限。

MyGo仍通过WebView2呈现Vue页面，浏览器和前端数据会继续占用内存。要评估框架本身差异，应在相同数据、相同页面、相同缓存策略、相同窗口数和运行时长下多次测量；上面的不同版本现场数据没有控制这些变量。
