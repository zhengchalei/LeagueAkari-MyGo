# Go 自动化范围

`New(client, store, emitter)` 只创建控制器，不启动轮询。宿主显式调用 `Run(ctx)`；取消上下文停止轮询与当前请求。`Tick(ctx)` 用于 mock 验证。

设置沿用 `auto-gameflow-main`、`auto-select-main` 命名空间与原键名，运行状态由 `State()` 按命名空间返回。`SetSelectGroups` 接受原 Akari 的模式配置组，不猜测历史 groupId。

每次 `Tick` 完成后发布变化的状态字段；取消、临时停用和待邀请好友变更即时发布，沿用 `mobx-utils-main` 的 `update-state-prop/{namespace}:state` 事件，不需要宿主额外轮询状态。

已迁移：

- 自动点赞五种规则；仅本局队友包含预组队和随机匹配队友，只有“包含对手”规则会选对手。排除自己、机器人、已点赞玩家；实时核验票数，重复轮询不重复投票。关闭或修改配置立即取消后续请求。
- 自动接受（延迟、手动取消、当前 ReadyCheck 核验）、结算回房间（等待点赞完成）、延迟重连。
- 开启结算回房间时，跳过 PreEndOfGame 的 `missions-celebration` 任务庆祝序列；支持事件和轮询，两者不会重复提交。
- 自动匹配（房主权限、人数、邀请回应、排队状态、惩罚剩余时间、启动前复核）；按固定或预估排队时间取消，扣除本次排队初始惩罚时长，开启自动匹配时返回房间后再次入队。沿用原边界：停止匹配策略本身可在自动匹配关闭时取消当前排队。
- 房间邀请按游戏类型规则或默认规则接受/拒绝/忽略，接受优先，重复轮询不重复处理；开启离开状态保护时暂不处理邀请（沿用原实现，不主动拒绝）。
- 自动转交房主优先选择已准备且非观战队友，提交前核验成员仍在房间、自己仍是房主；保留自定义房间提示。
- 选/禁英雄及预选：当前位置优先列表、可选/可禁列表、队友预选冲突、显示/锁定策略、延迟；只操作当前用户的动作。
- 大乱斗备选席：优先列表、更高优先级换人、延迟、候选池限制与提交前可用性复核。关闭、临时停用、离开阶段会中止。
- 待邀请好友由 `SetFriendsToBeInvited` 配置，好友上线后补发邀请，检查邀请权限与已有房间成员；退出房间或好友被删除时清理。支持 `HandleLCUEvent` 及好友状态轮询。
- 大乱斗和海克斯大乱斗发送所属地图侧，支持仅本地 `celebration` 提示或队伍聊天，自己 cellId 为 0 也正确处理。
- 英雄交换按优先列表接受/拒绝、延迟并核验交换仍有效；交换开关独立于自动选人开关，临时停用会中止。
- 克隆模式仅提交自己的 `vote` 动作，沿用选人优先列表与可用性核验；竞技场允许原 `-3` 勇敢举动标记，其余模式不采用此标记。
- 自动选禁、换人和交易的提示使用仅本地可见的聊天类型，选人聊天建立前暂存，退出选人清空。

`auto-misc-main` 由 `internal/misc.Service` 提供：自动回复、离线锁、登录后签名/段位设置和手动应用。`respawn-timer-main` 由 `internal/respawn.Service` 提供：按原结构发布自己的复活计时，仅查询 LCU 与游戏 Live Client Data。

真实国服下的克隆投票、特殊竞技场标记和游戏聊天仍需在对应模式验证客户端接受情况；原 Akari 仅定义了 `vote` 状态，没有执行分支，本次使用 LCU 的 action PATCH 提交。测试不触发这些真实操作。

Mock 测试只验证业务编排，不会连接客户端、入队、选禁英雄或发送点赞。
